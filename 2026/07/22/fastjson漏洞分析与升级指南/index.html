Fastjson 漏洞事件分析与 JDK 1.6 项目升级指南

文档日期：2026-07-22
适用对象：使用 fastjson 的 Java 项目，尤其是 JDK 1.6 环境下的遗留项目

一、漏洞事件概述

1.1 最新漏洞：fastjson 1.2.68–1.2.83 远程代码执行（RCE）

发布日期：2026-07-21
发布方：阿里云安全团队
严重等级：🔴 严重（Critical）
漏洞发现者：FearsOff Cybersecurity 的 Kirill Firsov

漏洞原理

fastjson 1.2.68 至 1.2.83 版本存在一条远程代码执行漏洞。该漏洞的核心特征如下：

维度 说明
触发条件 fastjson 默认配置即可触发（AutoType OFF + SafeMode OFF）
前置要求 无需开启 AutoType，无需 classpath 上存在任何 gadget 类
部署条件 目标以 Spring Boot 可执行 fat-jar 模式运行（java -jar xxx.jar）
入口点 JSON.parse、JSON.parseObject(String)、JSON.parseObject(String, Class) 均可达
验证范围 Spring Boot 2.x / 3.x / 4.x，JDK 8 / 11 / 17 / 21 均已验证

⚠️ 重要提示：即使指定了目标 Class（如 JSON.parseObject(body, SomeDto.class)），也不能 作为缓解措施——攻击者可通过 DTO 中 Object/Map 类型的字段嵌套 payload。这是一种 “gadget-free” 利用方式，传统的移除危险类等缓解手段对此完全无效。

不受影响的情况

条件 原因
fastjson2 所有版本 架构上已消除此漏洞根因
SafeMode = true 在漏洞触发路径之前即拒绝所有 @type
noneautotype 版本 漏洞相关代码在编译期被移除
非 fat-jar 部署 plain java -jar、uber-jar、Tomcat/Jetty WAR 部署不满足触发条件
fastjson ≤ 1.2.60 不存在漏洞相关代码路径

1.2 关联漏洞：CVE-2025-70974

发布日期：2026-01-09
CVSS 评分：10.0（Critical）
影响版本：fastjson < 1.2.48
漏洞类型：CWE-829（包含来自不可信控制域的功能）

此 CVE 是对早期 fastjson autoType/JNDI 注入漏洞（CVE-2017-18349 的不完整修复）的正式编号。该漏洞在 2023-2025 年间被在野利用，包括 Androxgh0st 攻击组织利用其入侵美国大学基础设施用于托管 C2。

1.3 fastjson 漏洞历史时间线

时间 版本 事件
2017 ≤1.2.24 CVE-2017-18349：autoType 反序列化 RCE 首次曝光
2019 1.2.47 autoType 缓存绕过，1.2.48 修复
2020 1.2.68 引入 SafeMode 安全模式
2022 1.2.83 1.x 最后一个版本，发布 noneautotype 版本
2022 2.0.x fastjson2 发布，架构重写
2024 — fastjson 1.x 正式停止维护
2026-01 — CVE-2025-70974 正式编号（CVSS 10.0）
2026-07-21 1.2.68–1.2.83 最新 RCE 漏洞公告（默认配置即可触发）

二、核心问题：JDK 1.6 项目的困境

2.1 版本兼容性矩阵

组件 最低 JDK 要求 说明
fastjson 1.x（≤1.2.83） JDK 6 ✅ 可在 JDK 1.6 运行
fastjson2 JDK 8 ❌ 无法在 JDK 1.6 运行
Jackson 2.0–2.7 JDK 6 ✅ 可在 JDK 1.6 运行
Jackson 2.8–2.12 JDK 7 ❌ 无法在 JDK 1.6 运行
Jackson 2.13+ JDK 8 ❌ 无法在 JDK 1.6 运行
Gson 2.8.5 JDK 6 ✅ 可在 JDK 1.6 运行

核心矛盾：fastjson2（官方推荐的安全升级路径）最低要求 JDK 8，而 JDK 1.6 项目无法直接升级到 fastjson2。这意味着 JDK 1.6 项目不能走”迁移到 fastjson2”这条路。

2.2 JDK 1.6 项目面临的限制

  1. 无法迁移到 fastjson2：fastjson2 最低支持 JDK 8，JDK 1.6 项目在升级 JDK 之前无法使用
  2. 只能停留在 fastjson 1.x：1.x 最后版本为 1.2.83，且已停止维护
  3. 需通过配置手段加固：SafeMode 或 noneautotype 版本是在 JDK 1.6 下的主要防护手段
  4. 替代库版本受限：Jackson 和 Gson 的 JDK 6 兼容版本也较旧，可能存在各自的已知问题

三、JDK 1.6 项目升级方案（详细）

方案一：启用 SafeMode（P0 紧急修复 — 推荐首选）

适用场景：需要最快速地消除漏洞风险，且可以接受 AutoType 功能被完全禁用

SafeMode 在 1.2.68 及之后版本引入。开启后，无论白名单和黑名单如何配置，都会完全禁用 AutoType 功能，从根源上杜绝反序列化漏洞。

⚠️ 注意事项

  • 启用 SafeMode 后，所有依赖 @type 自动类型推断的 JSON 反序列化将失败
  • 需全局搜索代码中 JSON.parseObject()、JSON.parse() 的无 Class 参数调用，评估影响
  • 如果业务中使用了 @type 进行多态序列化，需改为显式指定类型
  • 建议先在测试环境验证，重点检查涉及接口返回值反序列化、消息队列消费等场景

方案二：切换到 noneautotype 版本（P0 替代方案）

适用场景：希望从编译层面彻底移除 AutoType 代码，比 SafeMode 更彻底

noneautotype 版本在编译时完全移除了 AutoType 相关能力，不再支持自动加载类，从根源上避免反序列化漏洞。

Maven 配置

可用的 noneautotype 版本

Maven 坐标 说明
com.alibaba:fastjson:1.2.83_noneautotype 推荐：1.x 最后版本的 noneautotype 变体
com.alibaba:fastjson:1.2.71_noneautotype 1.2.71 的 noneautotype 变体
com.alibaba:fastjson:1.2.60_noneautotype 1.2.60 的 noneautotype 变体
com.alibaba:fastjson:1.2.54_noneautotype 1.2.54 的 noneautotype 变体
com.alibaba:fastjson:1.2.48_noneautotype 1.2.48 的 noneautotype 变体

建议直接使用 1.2.83_noneautotype，它是 1.x 最后版本的安全变体。

⚠️ 注意事项

  • noneautotype 版本完全不支持 AutoType，任何依赖 @type 的功能都会报错
  • 切换后需全面回归测试
  • 与 SafeMode 方案二选一即可，不需要同时使用

方案三：迁移到 Jackson（长期方案 — JDK 6 兼容）

适用场景：希望彻底摆脱 fastjson，迁移到社区更活跃、安全性更好的 JSON 库

JDK 6 兼容的 Jackson 版本

版本说明：

  • Jackson 2.0–2.7：支持 JDK 6
  • Jackson 2.8–2.12：需要 JDK 7
  • Jackson 2.13+：需要 JDK 8
  • 推荐使用 2.7.9（2.7.x 最后一个 release）

JSON 转 Map JSON.parseObject(json) mapper.readValue(json, new TypeReference<Map<String,Object>>(){})
获取字段 JSONObject obj = JSON.parseObject(json); obj.getString("key") JsonNode node = mapper.readTree(json); node.get("key").asText()

七、总结

要点 说明
漏洞性质 fastjson 1.2.68–1.2.83 默认配置下即可触发 RCE，”gadget-free” 利用方式
JDK 1.6 核心矛盾 fastjson2 最低要求 JDK 8，JDK 1.6 无法直接升级到 fastjson2
JDK 1.6 最优紧急方案 使用 1.2.83_noneautotype + SafeMode 双保险
JDK 1.6 长期方案 迁移到 Jackson 2.7.x 或 Gson 2.8.5（均兼容 JDK 6）
终极建议 条件允许时升级 JDK 到 8+，再迁移到 fastjson2 或最新版 Jackson

关键提醒：fastjson 1.x 已于 2024 年停止维护，即使使用 noneautotype 版本也只是权宜之计。对于 JDK 1.6 项目，最终出路在于升级 JDK 版本，以接入更安全的 JSON 库生态。
